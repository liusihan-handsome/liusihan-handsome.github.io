Git与Github的关系

一句话：Git是本地电脑的上对自己代码的不断开发的迭代和回溯，但是数据都在自己的本地电脑上如果电脑坏了，或者误删了某些的数据这样的话会导致数据的丢失。而Github是一个远程的代码管理平台，一方面可以存储自己的代码，另一方面是一个巨大的开源平台！

前提知识对齐：
首先要知道Git的存储区域：工作区(本地的电脑文件)、暂存区、提交历史。还有一个stash区（稍后解释） ，这些操作都是在本地电脑上实现的。

Git 三大区域

工作区 暂存区 提交历史
电脑上实际的文件 临时缓冲区 本地版本库（commit记录）
手动修改文件 git add 提交到此 git commit 提交到此
git restore 文件 撤销改动 git restore --staged 文件 撤销暂存 git reset / git revert 回退版本

分支与合并

核心：master分支，整个项目的主分支，要求项目是正常使用的在主分支上，不然一直在主分支上修改的话如果项目的代码并没有开发好导致主分支的逻辑出错，整个程序的话可能就会出错

所以要尽可以的确保主分支的正确，创建新的子分支在测试通过后合并在主分支上

比如自己在开发新的功能的时候，自己创建自己的开发分支进行代码的开发，这样的话如果切换到主分支的话，主分支不受子分支的影响（还是老功能），合并上才会修改添加新功能。
在合并新的代码功能到主分支的时候，需要先切换到master分支上在合并

合并后可以将feature/due-time删除

但是在实际的开发中并不是一条命令就可以实现合并的，会出现代码的冲突：
核心原因还是：可能相同的代码位置出现不同的代码选择，git并不能自己确定保留谁这个要自己解决这个冲突。比如mater在某一行的代码显示的是1，但是要合并all分支上的这一行的代码的内容确实2，git并不知要保留1还是2，就会发生冲突。

eg： 创建 feature/due-time分支和feature/complete -all ，先将feature/due-time分支合并到主分支上，在将feature/complete -all合并就可能出现merge failed，显示合并失败。

处理冲突的方式就是使用Vim编译器或者code打开冲突文件可以使用git status查看冲突的文件，修改好冲突后，在将本次的修改add和commit提交。

Rebase命令

在实际开发新功能的时候，开发的周期可能会很长，但是这个过程中master会不断更新迭代，你的开发分支功能实现慢，如果等到开发完成在合并此时的主分支可能已经迭代了很多次了，这个时候在合并的话就会有更多的冲突甚至代码不兼容的情况。这个时候就要用到git rebase 命令。
本质上就是不断的在主分支的改动下往后接，不断的改分支的起点，这样的话冲突可能小一点。
一个个commit的改，处理冲突使用编译器。


Stash命令

本质上这个命令的使用就是：在我们开发的过程中开发的代码采写一半，突然有个紧急的BUG需要修复，此时我们必须暂定新功能的开发，回到bUG分支上修改代码，但是此时分支上的代码是个半成品，如果直接commit的话半成品会出错，这个时候就引出了stash命令，将工作区和暂存区保存隐藏起来。bug修复好提交过在恢复过来。

worktree

但是stash适合单个分支的开发，如果开发多个分支的话，就需要不断的git stash和git stash pop
,太繁琐了，根本的原因还是因为，一个项目目录在同一时刻只能放一条分支代码，如果开一个新目录，两个目录互不干扰，引出来worktree。
多个workree有自己独立的工作区和暂存区但是共同一个提交历史。

将Git和Github建立连接

因为git的所有操作都在本地的电脑上，还需要和远端的github建立连接。
和github建立连接要输入密码跟登录账号一样，github要通过密码和确定是你本人在操作提交这个信息，密码就是密钥。

然后在github上创建新仓库

之后就可以使用 : git add 、git commit 、 git push。
