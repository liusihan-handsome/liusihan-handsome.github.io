忽略文件 .gitignore

有些时候我们不想把某些文件纳入版本控制中，比如数据库文件，临时文件，设计文件等在主目录下建立”.gitignore”文件，此文件有如下规则：

  1. 忽略文件中的空行或以井号（#）开始的行将会被忽略。
  2. 可以使用Linux通配符。例如：星号（*）代表任意多个字符，问号（？）代表一个字符，方括号（[abc]）代表可选字符范围，大括号（{string1,string2,…}）代表可选的字符串等。
  3. 如果名称的最前面有一个感叹号（!），表示例外规则，将不被忽略。
  4. 如果名称的最前面是一个路径分隔符（/），表示要忽略的文件在此目录下，而子目录中的文件不忽略。
  5. 如果名称的最后面是一个路径分隔符（/），表示要忽略的是此目录下该名称的子目录，而非文件（默认文件或目录都忽略）。

总结

上面的是我开学习git和如何自己写自己的博客的时候了解的所有内容，写了这篇文章，方便自己记忆也验证自己的所学

我在总结一下一个完整的git过程

今天我学会了安装Git。 保存好，回到 Git Bash（确保当前目录是 my-notes 文件夹里）。

第一步：把文件放进「暂存区」 git add 学习笔记.md
💡 小概念：Git 有个很重要的地方叫「暂存区」。你改完文件，先 add 一下，就相当于把这次要保存的改动先放到一个「待提交篮子」里。好处是：你改了好几个文件，可以挑着提交，不是一股脑全存进去。 如果想把所有改动都放进暂存区，可以直接写： git add .

第二步：正式提交到本地仓库 git commit -m “新增第一篇Git学习笔记”💡 小概念：commit 就是提交。执行完这一步，这次的改动就被永久记录下来了，生成了一个版本。引号里的文字叫「提交信息」，用来写清楚这次改了什么，以后回看历史的时候一眼就能看懂。 第三步：推送到云端Gitee git push 刷新一下你的 Gitee 仓库网页，是不是看到文件已经传上去了？ 恭喜你，你已经走完了 Git 最核心的一套流程：修改文件 → add 暂存 → commit 提交 → push 推送。 以后每次写笔记，都是重复这三步。

进阶一：看看我都改过什么——查看历史版本 写着写着你想看看自己一共提交了几次，每次都改了啥，怎么办？ git log 回车之后，你会看到一条条提交记录，每条都有： 一长串字符（版本号）、作者、时间、你写的提交信息。 按 q 键可以退出查看。
💡 小概念：每一次 commit 都会生成一个唯一的版本号。以后想回退到某个版本，就是靠这个版本号来找。 如果想看更简洁的版本记录，可以输： git log –oneline 每条记录只显示一行，清爽很！

进阶二：写崩了？一键回退到之前的版本 假设你手滑把笔记内容改错了，还提交了，想回到上一个正常版本。别慌，Git 救得了你。 先用 git log –oneline 找到你想回去的那个版本号（复制前几位就行）。 然后输入： git reset –hard 版本号 比如： git reset –hard a1b2c3d 瞬间，你的文件就变回了当时那个版本的样子。 ⚠️ 提醒：–hard 会直接覆盖掉当前工作区的内容，用之前确认好你要回退。新手阶段，重要内容先备份一份再操作也不丢人

进阶三：分支是什么？举个例子你就懂了 很多人觉得分支难，其实特别好理解。 想象一下：你现在笔记正文写得很稳定，你想加一段实验性的内容，又怕写乱了正文。怎么办？ 你可以「复制一份正文」，在副本上随便改，改满意了，再把改动合并回正文里。 这「副本」，就叫分支。

默认我们一直在 master 主分支上写东西。 新建一个分支 git branch 实验分支 切换到新分支git switch 实验分支 现在你就在「实验分支」上了，随便改笔记、加内容，怎么折腾都不影响主分支。改完照常 add、commit。 合并回主分支 实验成功，想把内容合到主分支里：先切回主分支 git switch master执行合并 git merge 实验分支 搞定！主分支就拥有了实验分支里的改动。 删除用完的分支 合并完，实验分支就没用了，可以删掉： git branch -d 实验分支

💡 小概念：多人协作的时候，分支就更重要了。每个人在自己的分支上写自己的代码，互不干扰，写完再合并到主分支。这样主分支永远是稳定可用的。

新手最容易踩的3个坑

坑1：改完文件直接 git push，报错。 记住顺序：先 add，再 commit，最后 push。少了中间任何一步都不行。

坑2：commit 信息随便写个「更新」「修改」。 过一个月你回头看，根本不知道这次改了啥。写清楚「新增了什么」「修复了什么」，以后会感谢自己。

坑3：在 master 主分支上瞎改，改崩了找不回来。 养成习惯：做大改动之前，先新建一个分支，在分支上折腾，没问题了再合并回去。 写在最后 Git 这东西，光看教程永远记不住，一定要亲手敲几遍命令。

你就拿自己的笔记当例子，新建、提交、回退、开分支，来回操作个两三次，自然而然就熟了。 刚开始记不住命令很正常，收藏这篇文章，忘了就翻出来看一眼。用得多了，就成肌肉记忆了。 祝你早日把 Git 用得飞起，再也不用被一堆「最终版」文件折磨～
