初学者学习git

文档已创建。后续按公众号知识卡片风排版写入正文、配图、封面方案、备选标题和内容验真。
Git小白入门：从0到1把你的笔记存进云端仓库
很多刚接触编程的朋友第一次听到 Git、仓库、提交、分支这些词，头都大了。这东西到底是干嘛的？我写个代码、记个笔记，为什么非要用它？
别急，今天咱们不讲虚头巴脑的概念，就拿「写一篇学习笔记」这件事当例子，带着你一步一步操作，做完你自然就明白 Git 是啥、怎么用了。
01 先搞懂一件事：Git到底帮我们解决什么问题？
你有没有过这种经历：
一篇笔记改了好多版，文件名变成「笔记.md」「笔记_最终版.md」「笔记_最终版_打死不改了.md」……最后自己都分不清哪个是哪个。
写了半天不小心删错了内容，找不回来，心态崩了。
和同学一起写一份报告，你改完发给他，他改完再发给你，来回传文件，版本乱成一锅粥。
Git 就是来解决这些问题的：它帮你记录文件的每一次修改，随时可以回看、回退，还能多人一起协作编辑。
而 Gitee 就相当于一个云端仓库，你把本地的修改同步上去，换电脑也能接着写，还不怕文件丢。
话不多说，开干。
02 第一步：准备好工具
安装Git
去 Git 官网或者淘宝镜像下载安装包，Windows 系统一路点下一步就行。
安装完右键桌面，能看到「Git Bash Here」这个选项，就说明装好了。以后我们输命令都在这里面输。
注册一个Gitee账号
打开 gitee.com，注册一个账号，就跟注册普通网站一样，很简单。
给Git报个到：设置你的名字和邮箱
打开 Git Bash，输入下面两行，把引号里换成你自己的信息：
git config –global user.name “你的名字”
git config –global user.email “你的邮箱@xxx.com”
💡 小概念：这一步是告诉 Git「我是谁」。以后每一次提交修改，都会带上你的名字，就像签字确认一样。–global 表示全局生效，你这台电脑上所有项目都用这个身份。
配置免密登录（很重要）
每次上传代码都输密码太麻烦了，我们配置一下 SSH 密钥，以后就能一键上传。
还是在 Git Bash 里输入：
ssh-keygen
一路按回车，不用改任何东西。
执行完之后，输入下面这条命令查看你的公钥：
cat ~/.ssh/id_rsa.pub
把输出的一长串内容完整复制下来。
打开 Gitee 网页 → 右上角头像 → 设置 → SSH 公钥，把刚才复制的内容粘贴进去，点确定。
验证一下有没有成功：
ssh -T git@gitee.com
第一次会问你是否继续，输入 yes 回车。如果看到欢迎你的提示，就说明配置成功了！
💡 小概念：密钥分「公钥」和「私钥」。公钥你放到 Gitee 上，私钥留在你自己电脑里。两者配对成功，Gitee 就知道是你本人在操作，不用每次输密码。私钥千万别发给别人。

03 第二步：创建你的第一个云端仓库
我们的目标是：在 Gitee 上建一个仓库，用来存放你的学习笔记。

  1. Gitee 首页右上角点「+」→ 新建仓库
  2. 仓库名称：比如 my-notes（注意路径要用英文，不能有中文和空格）
  3. 仓库介绍随便写：我的学习笔记仓库
  4. 下面三个初始化的复选框都不要勾，直接点创建
    创建完你会看到一个空仓库页面，上面有一串 SSH 格式的地址，长这样：
    git@gitee.com:你的用户名/my-notes.git
    把这个地址复制下来，待会儿要用。
    04 第三步：把云端仓库「搬」到你电脑上
    在你电脑上找个地方，新建一个文件夹，比如叫 gitee-projects。进去之后右键打开 Git Bash。
    输入：
    git clone 刚才复制的仓库地址
    比如：
    git clone git@gitee.com:xxx/my-notes.git
    回车之后，云端的空仓库就被下载到你本地了。
    💡 小概念：clone 就是克隆。把远程仓库完整地复制一份到你电脑上，包括以后所有的版本历史。这一步只需要做一次。
    05 第四步：写一篇笔记，提交上传
    进入刚克隆下来的 my-notes 文件夹，在里面新建一个「学习笔记.md」文件，随便写点内容，比如：

Git学习笔记

今天我学会了安装Git。
保存好，回到 Git Bash（确保当前目录是 my-notes 文件夹里）。
第一步：把文件放进「暂存区」
git add 学习笔记.md
💡 小概念：Git 有个很重要的地方叫「暂存区」。你改完文件，先 add 一下，就相当于把这次要保存的改动先放到一个「待提交篮子」里。好处是：你改了好几个文件，可以挑着提交，不是一股脑全存进去。
如果想把所有改动都放进暂存区，可以直接写：
git add .
第二步：正式提交到本地仓库
git commit -m “新增第一篇Git学习笔记”
💡 小概念：commit 就是提交。执行完这一步，这次的改动就被永久记录下来了，生成了一个版本。引号里的文字叫「提交信息」，用来写清楚这次改了什么，以后回看历史的时候一眼就能看懂。
第三步：推送到云端Gitee
git push
刷新一下你的 Gitee 仓库网页，是不是看到文件已经传上去了？
恭喜你，你已经走完了 Git 最核心的一套流程：修改文件 → add 暂存 → commit 提交 → push 推送。
以后每次写笔记，都是重复这三步。

06 进阶一：看看我都改过什么——查看历史版本
写着写着你想看看自己一共提交了几次，每次都改了啥，怎么办？
git log
回车之后，你会看到一条条提交记录，每条都有：
一长串字符（版本号）、作者、时间、你写的提交信息。
按 q 键可以退出查看。
💡 小概念：每一次 commit 都会生成一个唯一的版本号。以后想回退到某个版本，就是靠这个版本号来找。
如果想看更简洁的版本记录，可以输：
git log –oneline
每条记录只显示一行，清爽很多。
07 进阶二：写崩了？一键回退到之前的版本
假设你手滑把笔记内容改错了，还提交了，想回到上一个正常版本。别慌，Git 救得了你。
先用 git log –oneline 找到你想回去的那个版本号（复制前几位就行）。
然后输入：
git reset –hard 版本号
比如：
git reset –hard a1b2c3d
瞬间，你的文件就变回了当时那个版本的样子。
⚠️ 提醒：–hard 会直接覆盖掉当前工作区的内容，用之前确认好你要回退。新手阶段，重要内容先备份一份再操作也不丢人。
08 进阶三：分支是什么？举个例子你就懂了
很多人觉得分支难，其实特别好理解。
想象一下：你现在笔记正文写得很稳定，你想加一段实验性的内容，又怕写乱了正文。怎么办？
你可以「复制一份正文」，在副本上随便改，改满意了，再把改动合并回正文里。
这「副本」，就叫分支。
默认我们一直在 master 主分支上写东西。
新建一个分支
git branch 实验分支
切换到新分支
git switch 实验分支
现在你就在「实验分支」上了，随便改笔记、加内容，怎么折腾都不影响主分支。改完照常 add、commit。
合并回主分支
实验成功，想把内容合到主分支里：

  1. 先切回主分支
    git switch master
  2. 执行合并
    git merge 实验分支
    搞定！主分支就拥有了实验分支里的改动。
    删除用完的分支
    合并完，实验分支就没用了，可以删掉：
    git branch -d 实验分支
    💡 小概念：多人协作的时候，分支就更重要了。每个人在自己的分支上写自己的代码，互不干扰，写完再合并到主分支。这样主分支永远是稳定可用的。
    【文中插图落位：分支概念示意图｜主分支是一条直线，实验分支从中间分出去又合并回来的流程图，直观展示分支并行开发】
    09 最后：一张图记住核心流程
    不用死记硬背所有命令，日常用得最多的其实就这几步：
    写代码/写笔记 → git add .（放进暂存区）→ git commit -m “本次改了啥”（提交到本地仓库）→ git push（推送到云端）
    想查看历史 → git log
    想回退版本 → git reset –hard 版本号
    想开分支写 → git switch -c 分支名
    10 新手最容易踩的3个坑
    坑1：改完文件直接 git push，报错。
    记住顺序：先 add，再 commit，最后 push。少了中间任何一步都不行。
    坑2：commit 信息随便写个「更新」「修改」。
    过一个月你回头看，根本不知道这次改了啥。写清楚「新增了什么」「修复了什么」，以后会感谢自己。
    坑3：在 master 主分支上瞎改，改崩了找不回来。
    养成习惯：做大改动之前，先新建一个分支，在分支上折腾，没问题了再合并回去。
    写在最后
    Git 这东西，光看教程永远记不住，一定要亲手敲几遍命令。
    你就拿自己的笔记当例子，新建、提交、回退、开分支，来回操作个两三次，自然而然就熟了。
    刚开始记不住命令很正常，收藏这篇文章，忘了就翻出来看一眼。用得多了，就成肌肉记忆了。
    祝你早日把 Git 用得飞起，再也不用被一堆「最终版」文件折磨～
